# 版本闸：改一个已存在的文件，要求手上有它当前版本的读

`Edit` 一个已存在的文件之前，这次对话里必须有一次对它**当前内容**的 `Read`。判据是文件全文的
sha256：`Read` 走过时在那条 `ToolMessage` 的 `additional_kwargs` 上留一个读标记
（`src/agents/readBeforeWrite.ts:195`），`Edit` 进来时现算一次哈希去比（`:205`），对不上就拒绝，
拒绝理由钉住（`:219`）。**写永不刷新标记**——任何一次成功的写都改变哈希，因而作废此前所有的读，
所以连续两次改同一个文件之间必须重读。

**这不是在修一个正在发生的 bug，读到这份文件的人不要把它读成 bugfix。** deer-flow 有这个失效模式的
实证（`read_before_write_middleware.py:1` 逐字：_the same report section appended five times_），
我们没有。**但「我们没有」的理由，本决定第一版说错过一次，订正如下。**

第一版写的是「`.mimicc` 五条 session 里 `Write`/`Edit` 出现 0 次，所以我们不会等出来，这个仓库
自己从不触发它」。**后半句是错的**：它把「那五条 session 的用法」说成了「这个工具的性质」。
`Write`/`Edit` 早在 `633ea63`（2026-08-12）就进了工具表，**早于那五条 session**，所以 0 次只说明
那五条恰好全是只读任务——跑探针、检索、读源码。`repro/43` 给了它三个**不指定工具**的真实写码任务，
**3/3 格都伸手拿了 `Write`/`Edit`，共 6 次调用**：等得出来，而且第一个任务就来。

站得住的是另一句：**缺的不是「写」的实证，是「不读就写」的实证。** 同一支探针里闸 **0/3 次拦下**
——要改一个已存在文件的那一格，模型自己就走了 `Read → Read → Edit → Edit`。所以「判据只能是探针
驱动的」这条验收方式没有变（`repro/41`），但它的理由不是「我们从不写」，而是**「我们写的时候，
模型自己先读了」**。

装它的理由也因此没有变：**它是这个仓库里第二个「模型够不着的那一层」**，第一个是权限门
（ADR 0007）。模型可以不遵守一句写在文本里的要求，但它绕不开一个跑在工具前面的纯函数。

## 判据：有效反馈的五项

装不装一个反馈机制，按下面五项判；不满足的不装。五项是从三家一手 harness 的源码里挣出来的，每条的
出处带文件行号记在 `.scratch/deterministic-gate/research/03-what-feedback-actually-is.md`。

1. **确定性观测。** 观测必须是 harness 自己算得出的量，不是模型的自述。这里是文件全文的 sha256，
   deer-flow 同（`_content_hash`）。**「你读了吗」这种问句不是观测。**
2. **精确触发。** 五项里最脆的一项，而且量得出来它差点弄死一个机制：hermes 的 verify-on-stop 因为
   在没东西可验的 doc/markdown/skill 编辑上也放炮，**被默认关了三天**（`60f58a2b9` 关，
   `4dbd869ab` 开回来），病历逐字是 _more noise than signal_（`config.py:5962`）。
   **修法是收窄触发条件，不是删掉机制**——它今天默认仍是 `"auto"`，仍接在循环上。
3. **结构化后果。** 后果要分档，分档依据是显式字段而不是措辞的轻重。deer-flow 的 `tool_progress`
   用 `recoverable_by_model` 决定一个警告能不能升级成阻断，理由逐字
   _blocking would prevent a legitimate retry with different parameters_。
4. **一条诚实的出路。** 拒绝必须告诉模型做什么才能过去，否则它只会原地重试同一个调用。
5. **产物的存续期要匹配它的作用期。** hermes 的两条合成消息不落盘（`run_agent.py:228-234`），
   理由逐字：_poisons the resumed transcript_，且 _breaks prompt-prefix cache reuse_。
   这一项有两个方向——**拒绝**说明一个动作为什么没发生，作用期长，所以钉住；**提醒**只改这一跳的
   方向，作用期一跳，所以不进历史。后一半已经写在 `CONTEXT.md` 的「钉住」词条里。

## Considered Options

**抄 deer-flow 的临界区（否决）**——它把闸检查与工具执行放进同一把按 `(scope, path)` 的锁里
（`read_before_write_middleware.py:18-21`），因而顺带保证了「标记哈希的是模型真看到的那一版」。
**我们抄不动**：`withPathLock`（`src/tools/workspace.ts:37`）是 promise 链锁、**不可重入**，闸先
拿锁、工具体再拿就死锁。替代解是两层——哈希比对关跨回合与跨重启的窗口（标记活在消息里，持久），一个
即时的「已放行」集合 `inFlight`（`:112`）关同一批次内的并发（判定到放行之间是同步段，靠 JS 单线程
不可打断）。**代价写明：`Read` 之后另读一次盘来算标记，中间有一个微窗口，由 fail-open 兜住。**

**只写一句「改之前先读」（否决）**——`repro/39` 量到一句没有观测支撑的纯文本要求没有效力。
**但这个结果不能拿来否定反馈本身**：那句话连触发条件都没有，它落在上面五项的表外，既不是有效的那
一行也不是会被嫌弃的那一行。三家 harness 里有效的反馈都在承重位上。

**把 `Write` 也纳入闸（否决，且是本决定中途引入又撤掉的一个缺陷）**——`Write` 本来就永不覆盖
（`src/tools/mutating.ts:49-53` 抛 _already exists and Write never overwrites_），而闸跑在工具
前面，纳进来只是**把一条准确的错误换成一条误导的**：`repro/41` 逐字抓到模型答 _I can't overwrite
it with Write without first reading it_ —— 而读了也没用，那条路本来就不通。**由此定下一条规矩：
一条已经被更严的规则覆盖的路，不该再被一条更松的规则覆盖，第二条只能让第一条更难读。**

**`Bash` 之后事后作废读标记（否决）**——多余。闸是在 `Edit` 那一刻才现算哈希的，带外改动**自动**
让标记对不上；而真正的洞是「用 `Bash` 写完之后再也不碰 `Edit`」，那种情况没有后续调用可拦，事后
作废也治不了。两头都不落地。

## 关键子决定

- **只管 `Edit`**（`:104` 的 `GATED_TOOLS`）。`echo x >> f` 也是写，但要认出它得解析 shell，
  **那不是二值判据**，而精确触发是五项里最脆的一项。新建文件不管，没有「旧版本」可言（`:203`）。
- **装在权限门内侧**（`kinds.ts` 的 `agentStack`，在 `PermissionGate` 之后）。两个都是
  `wrapToolCall`，顺序决定谁先说话：一条被硬地板拒绝的路径，不该被这个闸打开来读一遍再走向另一条
  拒绝。已写成 `tests/kinds.test.ts` 的断言。
- **读标记与钉住标记同址**（`additional_kwargs`，`PINNED_KEY` 在 `src/context/projection.ts:70`）。
  这不是巧合：投影决定模型看得见什么，闸的状态就该活在模型看得见的那一份里。**所以摘要吃掉那条读
  结果，标记跟着没，闸就再也过不去**——一道读着模型已经看不见的内容的闸，是一道错的闸。
- **fail-open**（`:207`）。闸自己算不出哈希（二进制、权限、竞态）时放行。**闸的失效不应该比没有闸
  更糟**：放行只是回到装它之前的行为，是零损失，而不是净损失。

## Consequences

三条已知缺口，写在这里而不是假装没有：**`Bash` 绕得过去**（这是逃生口那条词条的同一个边界，不是
遗漏）；**`Read` 在 64KB 处截断而标记哈希的是全文**，超过就出现「模型只看到一部分、闸照样放行」，
deer-flow 同样接受这一条；**上面那个微窗口**。

`repro/41` 答掉了单测答不了的那一问——**拦下之后模型接不接得住**。序列逐字是
`Read → Edit → Edit → [拦] → Read → Edit`：不是原地重试，也不是放弃，是按拒绝里说的去重读了。
反过来，同一支探针的第一格里，提示只说「just write it」没指定工具，模型手上有 `Write` 却**选了
`Bash`**，绕开了闸。**n=1，措辞也可能有诱导，诚实的说法是「不指定工具时，模型至少有一次选了不受闸
管的那条路」，不是「总是绕过」。** 这一格是缺口一的实测，不是它的量化。

`repro/43` 与 `repro/44` 后来把这一格量清楚了：**那次绕过是措辞驱动的。** 44 把那半句提示当变量、
其余一字不动，两臂各 5 次——照抄 ①a 的 A 臂 **5/5** 走 `Bash`（逐字都是
`printf 'REPLACED' > notes.md`），只删掉 _Do not read the file first — just write it._ 的 B 臂
**0/5**，全部自己走 `Read → Edit`（完全分离，Fisher 精确检验双侧 p≈0.008）；43 的三个自然写码任务里
`Bash` 也只做 `ls` 与 `bun test`，一次没拿来写。**缺口仍然是真的，但它不是模型的默认倾向**，而且真实
交互里还有一道防线：那条命令在 `auto` 关时判 `ask`（`decide()` 实测）——**关它的是确认门，不是版本
闸**，与词表「逃生口」说的是同一件事。

## 增补（2026-08-27）：Write 盖自己的章

**「要求一次 `Read`」改为「要求一次 `Read`，或你自己的 `Write`」。** commit `9956c0f`，
判决与执行在 `.scratch/rbw-tax/`（票 01 判、票 02 落地）。

实证：benchmark 的 csv-to-parquet 会话里，模型「`Write` 新建文件 → 立刻 `Edit` 它」被闸拦下
（24 圈轮 3 次、第四轮 2 次，存档逐条数出）——被拦的全是模型改**自己刚写的**文件，不是本闸要防的
「拿着旧版本改」；每次拦下白烧一圈 Read + 一圈 Edit。

判据：`Write` 只创建、永不覆盖，所以文件在 Write 之后的内容 = 模型刚发的字节——「知道当前版本」
是**事实**，不是豁免。盖章（写入后现算哈希，与 `Read` 的盖章同法）后：自己的 Edit 放行；
**任何外部改动（Bash、用户）都让哈希对不上，照样拦**——保护面不减，税消失。`Write` 落到已存在
文件时报错、不盖章，「Write never overwrites」的语义原样。词表（CONTEXT.md 版本闸/读标记）与
`readBeforeWrite.ts` 的注释同步更新。deer-flow 原版「writes never refresh」的规则不变——它没有
Write/Edit 的拆分，那个流在它那里不会精确触发。

## 增补（2026-08-28）：`Edit` 也盖自己的章

上一条增补给 `Write` 的理由（**自己写下的字节就是当前版本**）对 `Edit` 一字不差地成立：
它同样精确知道改完的字节。原来那句「写永不刷新标记」给的论证是
_「任何一次成功的写都改变哈希，因而作废此前所有的读」_——**这句是对的，但它论证的是
「旧读不再开门」，不是「不能盖新章」**。

Terminal-Bench run `2026-08-27__22-37-36` 给这个区别标了价：`Write → Edit → Edit`
在三道题里都卡在第二个 `Edit`（`blind-maze-explorer-algorithm`、`pytorch-model-cli`、
`.hard`），每次都逼一次「重读自己刚写完的文件」。修完复跑，被拦次数 2→0、1→0，
消息数 59→34、111→79（`.scratch/external-bench/issues/05-failure-triage.md`，C4）。

不变的两条仍有测试钉着：**只拿着过期的 `Read` 标记仍然被拒**；**自己改完之后被外部
（`Bash`、用户）动过，仍然被拒**——盖章在改动落盘之后现算哈希，所以外部改动照样对不上。
